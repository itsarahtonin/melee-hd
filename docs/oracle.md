# The oracle

melee-hd's simulation is checked against ssbm-rs at the `melee-hd-base` tag, whose ports are verified function by function against the original machine code. The oracle comes before any porting: every ported system is checked by it from its first commit.

## Levels

| Level | Reference | Compares | Status |
| --- | --- | --- | --- |
| Replay events | Slippi replays, which ssbm-rs reproduces | Slippi's pre-frame, post-frame, item and frame-start events, field by field, through the timeline rollback settled on | `melee-oracle compare` |
| Full state | ssbm-rs playing the same replay | The whole state every tick, as the captured-state checks compare it, against ssbm-rs's memory | `melee-oracle diff`: runs from the match's start or a trace tick, stops at the first difference or unported function |
| Captured states | ssbm-rs's lockstep captures (memory at a real call) | A game function run from a real game state on both sides, then the whole state | `melee-capture`: imports a captured state into melee-sim (scheduler, joint trees and everything on them, fighters, the stage) and compares melee-sim's state with memory; round trips on real captures come back clean. leaf-check's `stage` tests run Final Destination's and Battlefield's setup and processes from captures, its `camera` tests every camera function, and its `effects` tests every effect function and spawn every effect id from real states |
| Leaf functions | ssbm-rs's ports | Math, collision geometry and other code whose inputs and outputs map directly | `leaf-check`: the RNG, math, the SDK's and HAL's vectors, matrices and quaternions, collision geometry, stage and environment collision, controllers and rumble, and HSD's scheduler, animation, joints, references, display lists and shapes |

**Replay events.** ssbm-rs plays the 40-replay smoke set to the same recordings as the original code, with documented entry-frame and off-screen-flag differences in 12. A melee-hd recording is compared with the original replay through ssbm-rs's own comparison (`ssbm_slippi::compare`). This covers VS matches only, and only what Slippi records.

**Full state.** Replays leave out most of the game: menus, single-player modes, stage objects, the camera and most fighter fields. ssbm-rs's runner, with `STATE_TRACE=FILE`, writes the game's raw state at the end of every engine tick: the RNG seed, the player blocks, the stage, the camera, and every fighter, item and fighter joint. `melee-oracle trace-check TRACE REPLAY.slp` checks a trace against the replay it ran: each frame's post-frame fighter positions and percents must equal the trace's, bit for bit, one tick per frame. Two full smoke replays (Dream Land, 13,779 frames; Pokémon Stadium, 13,671) pass with no difference; a full match's trace is about 14 MB. Slippi's pre-frame data doesn't line up as exactly, because it is sampled partway through a tick. Function-level lockstep doesn't carry over, because melee-hd's data no longer has the original's layout.

With `STATE_TRACE_MEMORY=FROM..TO` (ticks, or `1` for all; trace version 3), each tick also carries main memory: the 4 KiB pages that changed since the tick before, XORed with what they held, every nonzero page at the window's first tick. Version 4 adds the time base at each such tick's end, which the audio timeline starts from when the diff takes up a tick or seeds the boot state. The main thread's stack and the GX FIFO are left out, as neither is game state: since version 5 their bytes are held at zero and the rest of the pages they share is recorded (before, the whole pages were left out, the OS heap descriptors after the FIFO with them). A whole match with memory is about 250 MB in the silent DSP model and about twice that in the sample-accurate one. The oracle's traces are made with Show Player Names off (`SLIPPI_PLAYER_NAMES=0`, a setting Slippi Dolphin has too): that optional playback code draws the players' names over the match and makes HUD objects for them, which melee-hd leaves to the presentation. They're made with ssbm-rs's default, sample-accurate DSP model, which `Settings::from_replay` plays replays with, as Slippi Dolphin recorded them. That doubles their size, because the voices' state in audio memory then changes every tick: the Fox vs Sheik match's is about 525 MB, against 258 MB silent. The Fox vs Sheik Final Destination replay's is made so, from ssbm-rs's checkout:

```text
SLIPPI_PLAYER_NAMES=0 STATE_TRACE=local/traces/v5-mixed/Game_20260129T133652.trc STATE_TRACE_MEMORY=1 \
  target/release/ssbm-run "$SSBM_DISC" --replay Game_20260129T133652.slp --fields 100000 \
  --port all --known local/replays/known-names0/Game_20260129T133652.txt
```

Runs with Show Player Names off take their known divergences from ssbm-rs's `local/replays/known-names0/`, not `known/`. The names' HUD objects are allocated ahead of others, so with names off a few heap addresses land 0x2500 bytes lower. Eight replays' known files record such addresses (in fields like a hitstun word that holds an object's address, never gameplay), and `known-names0/` holds those eight rewritten from names-off runs, plus copies of the other 178. If ssbm-rs's heap layout changes, those eight need regenerating in both folders.

`melee-oracle diff TRACE REPLAY.slp` plays the replay in melee-hd and compares its whole state with the trace's memory after every engine tick, through `melee-capture`'s comparer: the scheduler and everything its GObjs hold (joint trees with their animations, references, display objects and shapes, the fighters and every byte of their animation buffers the model knows, the stage objects), the stage, the camera, HSD's ID table, the audio driver's voices, the player blocks, the pad library, the button maps, the scene loop and its clocks, the VS match's controller, Slippi playback's state, the ruleset and UCF's pad buffer, the items' statics, and the display pass's statics (the current camera, the current and active lights with their slot masks, refraction's users, textures and projection, the background flash). Objects pair afresh each tick by where they are reached from. It reports the first tick (and its replay frame) that differs with the first 30 fields that do (`--all` for every one), or the first function no port covers (`code::unported`), named with its tick. The trace samples each tick before its frame's display pass, so the diff compares right after the tick and runs the display pass before the next one (`Match::step_replay_tick`, `Match::render`). The archives a started match loaded itself pair with where the original loads them by name (`Match::files`), a fighter's animations wherever its buffer holds them. `--fp hardware|slippi` picks the float mode (`gekko_fp`) the trace was made in: Slippi's for a replay as Slippi Dolphin plays it, the hardware's for a trace made with `--fp hardware`. To look past another part's seam, `--stand-in ADDR[=VALUE]` lets an unported function return (melee-sim's `stubs`), and `--ignore TEXT,...` drops the differences that contain one of the texts. Without options it starts the match from the replay's settings (`Settings::from_replay`), as Slippi's playback codes do, and runs from the trace tick that ran the match's first engine tick. With `--from TICK` it imports the trace's state at the end of that tick through `melee-capture`, compares the import back with the memory it came from, and plays on from there; `--against TICK` compares the import with a later tick's memory instead, which shows the comparison telling states apart. `trace-info`, `trace-dump` and `trace-world` inspect a trace with memory.

On the Fox vs Sheik Final Destination replay (v5-mixed), the match runs from its start in Slippi's float mode with no stand-in: it compares every one of the trace's 11,928 ticks with no difference and no stale read, the whole audio state and the sound handles the fighters and items keep included (Sheik's needles, the fighters' hitboxes tested against them, her ledge hangs and Vanish among them; from tick 1223, replay frame 1099, Sheik turning into Zelda, `ftCommon_8007EFC8`, Zelda's specials and dress dynamics toggled by her scripts, back into Sheik, the KOs, smash charges and UCF's dashback turning the sleeping fighter's CPU stick, Fox's lasers and the fighters' attacks landing on Sheik's needles and the needles taking the hits, the items in reach of a fighter's grab, an item's tip), to the trace's end. Zelda is out until frame 2302 and again from 8440 to 9025. From tick 296 on, new thrown needles' variables hold words their flight never writes (`xDD4`, `xDDC`, `xDE0`, later `xDD8`), which the block keeps from the held needles it held before (whose owner pointer is the first word); they stay stale (`it::Var`, docs/engine.md), so the comparison leaves them out, and nothing reads them. Taken up from tick 200, play runs the remaining 11,728 ticks with no difference: a new item's unused hitboxes' joints (`x5D4_hitboxes[2]` and `[3]`, `hit.jobj`), words the item never writes and keeps from the freed item its block held before, now import as the live joints they point to. From ticks 120 and 400 play stops on those words in tick 609 all the same (the joint they point to there is freed by the tick, and dangles), from 1000 in tick 1061. The audio state compares from the first tick because the match's start runs, on the boot state's timeline, the boot's last scene's end (its last frame's render and copy, and the wait for the next retrace), the announcer's bank load, the scene's file loads where the original makes them (the fighters' `PlCo.dat` and their effect files among them) and the music's start. The pad library's queue follows the timeline: the polls the pad alarm queued while the scene set up (14 on this replay, beyond the one the boot state's queue held, which wrap the five-entry queue's `qwrite` from 2 to 1) are queued before the loop's flush, and the first round ticks on the one it leaves. In play the alarm (every 675,000 time base ticks) runs a little faster than video fields (675,675), so every thousand frames or so the scene loop finds a second poll queued by the time it counts them: that round ticks twice and renders once, and for the frames before it a poll waits in the queue. The diff queues each poll the timeline counts and runs the display pass only after a round's last tick. Taken up from any tick, the import compares back with no difference (ticks 120, 200, 400, 1000, 2500 and 5000 checked, the background flash's state and the magnifier's bubbles included), and play goes on until a tick like 609 above, where a new item holds a joint word its block kept from its last item: from 2440 to 2867, 5000 to 6353, 7000 to 7166 and 11000 to 11022, and from 3000 to 7649, where a fighter's last damage source (`dmg.x1868_source`) points to a GObj freed before the import, with no difference or stale read before; from 9000 play reaches the trace's end. **Boot state.** A match that starts from the replay's settings can't hold what the boot and the menus left in the original's memory. - the pad library: the queue's read and write positions, queued count and queued polls, the reset button, and the master, copy and game statuses (the seeding refuses a boot state where a rumble script the menus started still runs);
- the random seed (`*HSD_RandSeedPtr`) as the menus' draws leave it; Slippi's playback replaces it with the replay's when the match starts;
- the audio library: the AX library, the synth, the driver and the game's audio library as the boot initializes them and the menus leave them, with the sound bank they loaded and the audio timeline at the boot state's time base. Load timing isn't modeled: the bank is there from the start.

**Captured states.** Game code needs real states to run from: a fighter mid-action, with its joints, animations and stage. ssbm-rs's lockstep captures (`CAPTURE=DIR CAPTURE_FUNCS=NAME,...`) save main memory and registers at real calls. `melee-capture` finds which disc archives are loaded where (by header and contents; the game writes into some, such as fighters' action tables), then imports the state into a `Game`: the GObj scheduler with its processes, every joint tree with its animations, references, display lists and shapes, the fighters through their generated mirrors, and the stage (`stage_info`, the stage objects' user data with their variables typed for the stage, the stage parameters the game writes into, the collision geometry and islands, fog, lights, the game camera with its camera boxes, the player slots, game mode and controllers the camera reads, the random seed and HSD's ID table, and the effects and the particle system: every effect, efLib's globals and the fighters' deferred spawns, the effect banks, particles, generators, app-SRTs, point joints and the display's sorting state). Afterwards it compares a `Game` with memory, pairing objects by where they're reached from, so objects either side created since pair too. A port runs from the imported state while ssbm-rs runs the call from the same memory, and the two states are compared. Pointers the importer doesn't model yet (static data in the executable, item user data) are listed rather than guessed. A check runs its saved calls on `LEAF_CHECK_WORKERS` threads (2 by default, each with its own reference), so a suite run with `--test-threads=2` keeps to about four cores.

Besides single calls, a captured state can drive longer runs: leaf-check's `last_stage_ticks` runs Final Destination's stage processes alone for 6,400 ticks on both sides from one capture (phases 1 through 8 of its background cycle), `battle_stage_ticks` runs Battlefield's for 9,000, and the `on_state` tests call functions no capture reached on a real stage. The camera's tests also run perturbed copies of captured states (both sides start from the same changed memory) to reach values and branches the replays don't, and enter its special modes from VS states with random controllers. Where objects are freed and new ones made, both sides are paired afresh by where objects are reached from, since the heap reuses blocks by address and pools by last freed.

The audio driver is too (`leaf-check`'s `audio` tests): the importer brings in the driver's virtual voices and globals, the synth's nodes, loaded effects and globals, the AX library's voices, parameter blocks and stacks, and the sound bank (from its loaded copy), and the comparison checks them byte for byte. Their calls are saved with the runner's `CAPTURE_INTERACTED=1`, since every audio function masks interrupts. Their schedule has a check of its own: ssbm-rs's runner records every audio call game code makes, the audio frames and the audio state at every tick's end (`AUDIO_TIMELINE`), and the check replays the calls from a captured tick with melee-sim's timeline placing the frames, comparing tick start and end times and the whole audio state every tick over whole matches: a Final Destination singles and a four-player Battlefield teams replay (about 10,000 ticks each, clean), the singles again with ssbm-rs's sample-accurate DSP (`AX=1`, where the music refills read the disc), and a Pokémon Stadium match whose transformations load during play. The recorder also logs the game's own disc load requests, which the check replays with their waits. A fifth timeline starts at the boot's last tick (`AUDIO_START=0`) and replays the Final Destination match's scene entry: the library's bank choice and loads, the file loads and the music's start, with game code's own time between ticks taken from the log's time base and the entry's audio frames placed where the log has them. The sound bank functions also have saved calls of their own (`bank_calls`, `match_bank_choice`, `bank_group_remove`, `bank_deflag_moves`). The music stream's start and callbacks and the audio library's tick have saved calls of their own.

The VS match is checked the same way (`leaf-check`'s `vs` and `player` tests): the importer also brings in the player blocks, the pad library (queue, rumble and statuses), the button maps, the scene loop's state and frame clocks, the VS controller, the live standings, the pause screen and the player library's counters, and compares them back. Its captures come from the debug VS mode's random matches (`--mode e --matches`), whose code Slippi's playback codes don't patch (in replay runs they patch the VS scene's frame, setup and entry, and the pad library). Calls the runner never saves (those that load files or reach the audio driver) run from other functions' captured states; the player blocks' and the match's accessors run as random sequences from captured states, comparing every value read and the blocks after each step.

Fighter creation is checked from the states just before a VS match creates its fighters (`leaf-check`'s `fighter_create`): every slot's fighters are created on both sides and the whole state compared after each, the fighters' new joint trees, parts, attributes, DObj lists, dynamic bones, shadows and lights, the player blocks and the fighter globals with it. The debug VS mode reads fighters' files from the disc inside `Fighter_Create`, which the reference's side does from the disc while melee-sim's side is handed the same files.

The fighters' attack collision (`Fighter_procAttackColl`) is checked from its calls in running matches (`leaf-check`'s `fighter_procs`), each also run again with the other fighter's first hitbox switched on over the fighter and, by the call, the fighter's own box over it on the ground (clanks), its shield up, or both fighters' thrown boxes live: the hits, tips, clanks and shield hits, the damage logs, the knockback and damage result, the hit sounds and the statistics they reach, the effects they spawn compared with the rest, and the attack statistics stood in for on both sides. The same check runs the collision results (`Fighter_procCollResolve`), from real calls and again with one of the attack collision's results given (a tip, a shield hit, a clank, a dealt hit, a shield push, a held hitlag), the camera process and the fighters' light. The dynamic bones (`Fighter_procDynamics`) and the legs' reach (`Fighter_procIK`) are checked from their calls there and in a replay, again with wind sources given, a flat floor, other sizes, the air, a collider and Flat Zone, and with the legs' flags set and the model's root off the floor.

The fighter mirrors come from `tools/structgen`, which generates each game struct with an importer and a field-by-field comparer. `melee-oracle mirror-check TRACE` round-trips every fighter of a state trace through them.

**Slippi versions.** Slippi's online code set changed between versions, and a replay records the set it ran. melee-hd knows three (`game::slippi::CodeSet`): Slippi 3.19's (the author's replays); 3.16's, which 3.17 ships word for word and 3.15 already has (the `erickfm/melee-ranked-replays` dataset's replays); and 3.14's, which is 3.16's without WhispyBlowDirFix (`8008653C`), so Whispy's blow direction counts dead and sleeping fighters as the original does. 3.19's and 3.16's gameplay codes match but for three of the determinism fixes, read from the replays' code lists:

- **Final Destination's background** (`8021AAE4`, in `grLast_8021AAB0`, on `bl grLast_8021B2E8`): 3.19's `C2` code saves the random seed, makes the call and puts the seed back; 3.16's is a `04` write of a nop, so the scene's timer never runs: no 30-second wait, no fog blends, and the background stays in its first phase all match. `proc_main` follows `Rules::codes`.
- **Nana's DI** (`800AC5B8`, in `ftCo_800AC5A0`): both clear `r30`, the register whose low byte becomes her stick Y; 3.19 also clears `r5`. Its host takes the variant from `Rules::codes` (`ft::cpu_move`, [the engine notes](engine.md)).
- **Pokémon Stadium's transformations**: 3.19 loads the next transformation's file when it's due, synchronously (`800165AC` and the hooks at `801C65C8`, `801D4760` and `801D457C`). 3.16 freezes the stage: `Online/Core/PreventFileAlarms/FreezeStadium` (`801D4578`, the instruction after the cycle's scale read) jumps to the cycle's epilogue (`801D4FD8`), so the stage stays the default one all match, the cycle draws no random number and its timer (drawn in the setup) never counts. The set also carries `Common/Preload Stadium Transformations` (slippi-ssbm-asm's names): picking the next transformation ahead while the cycle waits (`801D45EC`: `HSD_Randi(4)` drawn until it differs from `xE2`, kept at the stage's `xEC`, its file's load started with the game's asynchronous `lbFile_80016580` and a byte at `xF0` set), taking that pick when the timer runs out (`801D460C`, `801D4610`) and skipping the original's load (`801D4724`), and the byte cleared in the setup (`801D14C8`) and when the default stage settles back (`801D4F14`). All but the setup's line sit past the freeze's return, so with the whole set they never run; the setup's clearing of `xF0` does, and the comparison checks `xEC` and `xF0` with the rest of the stage's variables.

`Rules::from_codes` reads the version from the codes themselves: each known code lists the versions that ship it, every code of a list must belong to one version (`CodeError::Mixed` otherwise), and each rule must have all of that version's codes. A list that fits several versions plays as the first it fits whole, in the order 3.19, 3.16, 3.14: a list of only the codes all share plays as 3.19's. `melee-oracle rules REPLAY.slp...` prints what a replay's codes make, or why melee-hd refuses them.

**UCF versions.** UCF comes in two versions in Slippi replays (`game::ucf::Ucf`), each recognized by its codes and either going with any code set:

- **UCF 0.84** (`External/UCF 0.84/UCF`): all of Slippi 3.17's and 3.19's replays and most of 3.16's.
- **UCF 0.8** (`External/UCF 0.8/Logic`): all of 3.14's and 3.15's and some of 3.16's. It has three codes, at three of 0.84's places: dashback (`800C9A44`), shield drop (`800998A4`) and tumble (`800908F4`). It has no pad buffer, SDI, shield SDI, extended shield drop or down-smash out of crouch fix. Its dashback and tumble take the raw stick's travel from the pad library's queue, from the poll two before the one the tick took to that one, where 0.84's read its own buffer of each human fighter's last four ticks. Its dashback needs the stick past the dash threshold either way, not the way the turn faces, and turns Nana's CPU stick only for Popo. Its tumble lets a NaN stick fail where 0.84's goes on. Its shield drop works on any floor, needs the stick's horizontal timer past 3 rather than the roll's window, and takes the stick's distance as floats (each axis in raw units plus 2, over 80, squared and summed, at least 1) rather than in whole units.

ssbm-rs plays 3.16 replays with Slippi's playback codes, which run the recorded codes as they are (it keeps the original machine code of the functions they patch), and its replay check shows one difference from the recording: the pre-frame random seed at frames -123, 3877 and 7877 of the Ganondorf vs Captain Falcon replay, where ssbm-rs records the frame start's seed one draw on and the recording has the frame start's seed itself. 3.16's online codes set each frame's seed (the frame index in the high half over the match's seed) and record it as the frame starts; playback puts that seed back from a process of its own (`playback_restore_seed`). In those frames Final Destination's particle generator spawns (`hsd_8039EFAC`, `hsd_8039F05C`, `HSD_Randf`) after playback's process and before the fighters' inputs are recorded, so playback's recording shows its draw; the online game's shows none, so there the frame's seed was set after that draw. 3.19 recordings show the draw (the Captain Falcon vs Sheik replay's pre-frame seed at frame -123 is its frame start's one draw on), so 3.19's codes set the seed where playback puts it back. Playback restores only the frame start's seed, so in those three frames every later draw comes one step on from the online game's; nothing gameplay draws then here (every post-frame event matches, and the next frame's seed is put back), only the particles, which no replay records. A gameplay draw in such a frame would part any playback of a 3.16 replay from the online game. It isn't an ssbm-rs bug: ssbm-rs does what Slippi's playback codes do.

Playback's own set also patches fighter code: in `ftCo_8009DD94` (`+0x2FC`, the bone dynamics' end) it sets up every dirty matrix of the fighter's model (each joint with `0x40` and not `0x800000` in its flags, children before siblings, instances included), which `Running::swing_chains` does in a replay, and in `ftCo_800DEBD0` it reads the debug level as 0, which a retail disc's is anyway. At the match's end the recording codes copy the results into the VS scene's exit data (`gmVsMelee_VsExitInfo`) and rank them with `gm_80166378`, which matters once the exit data is ported.

These ports are checked in leaf-check's `replay` tests against ssbm-rs's ports made with the codes (`ssbm_game::playback`), from captures of replay runs (their header shows how to make them): the recorded inputs with their raw sticks at UCF's thresholds, the first frame's settling, UCF's stick history and SDI, the off-screen limits, the frame reads, stock steals, the seed restored each frame, the general codes' costume rules and the settings themselves. leaf-check's reference runs the patched port of every function whose codes a capture's memory holds (`register_patched`), so the fighter and VS checks on replay captures check the patched behavior too; the VS checks' `place_players` covers neutral spawns, and `input`'s pad library sequences run with the playback patch on a quarter of the time. **Leaf functions.** `leaf-check` loads the disc's `main.dol` into ssbm-rs's runtime, registers every port, and calls them one at a time, so melee-sim's functions are compared with ssbm-rs's input by input, in both float modes. Inputs are special values, random bit patterns and values spread over each function's useful range. Changing one bit of a constant makes the checks fail.

## Rules

- Floats compare by bit pattern. One ULP is a divergence.
- External events (a disc read completing, a camera snapshot) are inputs, recorded and replayed like controllers, never compared as state.
- A known difference must be explained and listed per replay, as ssbm-rs's known-divergence files are; a blanket exception is never accepted.

## Running the checks

The checks read three things that aren't in the repository, each named by an environment variable with no default. A check whose data isn't there skips with a message naming the variable or path (`cargo test -- --nocapture` shows it), so without them `cargo test` runs only the checks that need nothing; the `--ignored` frame and mix checks fail instead, since they are run on purpose.

| Variable | What | Read by |
| --- | --- | --- |
| `SSBM_DISC` | The NTSC 1.02 disc image (GALE01, revision 2) | Every disc-backed check, `melee-oracle`, `melee-bench`, the player |
| `SSBM_RS_LOCAL` | ssbm-rs's `local/` folder, where its runner writes captures (`calls/`), state traces (`traces/`), references (`player/`) and the benchmark matches' start traces (`bench/NAME.start.trace`) | leaf-check's captured-state checks, `melee-oracle`'s `diff` and `vanilla` tests, the frame and mix checks (`REFS` overrides), `melee-bench native` |
| `SLIPPI_REPLAYS` | A folder of Slippi replays, a folder a month as Slippi Launcher keeps them (the author's, not public) | leaf-check's `replay`, `slippi` and `audio` crowd checks, `melee-oracle`'s `diff` test, the Fox vs Sheik frames |

Each test's own variable (`FOX_CALLS`, `MATCH_CALLS`, `TRACE`, `REPLAY`, `BENCH_DIR` and the others its header names) still overrides its default. The benchmark matches' replays are in the repository, in `data/bench` ([performance](performance.md)). The data itself is made with ssbm-rs's runner (its `main` branch has every recorder these pages name) as each check's header and this page say.

The checks run before each change lands:

```sh
  target/release/melee-oracle diff "$SSBM_RS_LOCAL/traces/v5-mixed/$m.trc" data/bench/$m.slp --fp hardware
done

  "$SLIPPI_REPLAYS/2026-01/Game_20260129T170722.slp" --fp slippi   # and the other Slippi replays above
cargo test --release -p melee-sim -p melee-oracle -p melee-render -p melee-gpu -p melee-audio -p melee-input -p melee-player

```

Run filtered leaf-check tests (`--test NAME`) in a command of their own: with several packages, cargo applies a `--test` filter to all of them and skips the rest.

### Capture packs

ssbm-rs's runner saves each call as a file of its own (`NAME-callN.call`, a whole memory snapshot compressed), but the calls of one run share nearly all their memory. `pack-calls` puts a directory's calls into one `calls.pack` beside them, holding each distinct 4 KiB page once (compressed 64 pages to a block) with each call's name, registers and pages, and keeps the pack only when every call reads back from it byte for byte. ssbm-rs's `local/calls`, 21,042 calls in 168 directories, went from 114.4 GiB to 3.5 GiB this way.

```sh
cargo run --release -p melee-capture --bin pack-calls -- -r "$SSBM_RS_LOCAL/calls"   # every directory under it
cargo run --release -p melee-capture --bin pack-calls -- --verify DIR               # check a pack against the files left
cargo run --release -p melee-capture --bin pack-calls -- --unpack DIR               # the pack's calls back out as .call files
```

`Capture::read` takes a call from its directory's pack when the pack holds it and from its file otherwise, and the checks list a directory's calls from both, so a call's path is `DIR/NAME.call` either way and new captures can stay files until the directory is packed again: packing a directory that has a pack keeps the pack's calls whose files are gone and adds the new files. Once a directory's pack is verified, its `.call` files can go: `--unpack` writes them back as ssbm-rs's runner wrote them (zstd level 3), and on Marth's `fox-marth-fd` set the rebuilt files came out byte-identical to the originals, compressed bytes included, and packed again into the same pack. Each block is decompressed once per process and shared, so reading a call is copying its pages.

### leaf-check's speed

A captured-state check spends almost all its time around the call, not in it: running the function on both sides took about 12 ms of a call's 355 ms in `ftcommon_entries`. The rest was reading the call (58 ms of zstd), finding the loaded archives in memory and importing the state (100 ms), comparing the import with memory (79 ms), and after the run finding the archives again and comparing the whole state (107 ms), each again for every float mode and every case run from the same call. Looking symbols up by name in a 35,000-entry list inside the comparison's loops took most of the comparing. Now symbols come from a map made once, the archive scan skips places no disc file starts at, calls come from packs, and a test that runs several checks from the same calls (`ftcommon_entries`' cases, the characters' stand-ins answering no and yes and their neighbours' rounds) runs them as variants of one pass (`calls::run_variants`): each call is read once and imported, its round trip checked, once for every check and mode that prepares it into the same state, bit for bit. The checks, the calls and the comparisons are the same: each binary's output, every count in it, came out identical before and after.
