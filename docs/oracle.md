# The oracle

melee-hd's simulation is checked against ssbm-rs at the `melee-hd-base` tag, whose ports are verified function by function against the original machine code. The oracle comes before any porting: every ported system is checked by it from its first commit.

## Levels

| Level | Reference | Compares | Status |
| --- | --- | --- | --- |
| Replay events | Slippi replays, which ssbm-rs reproduces | Slippi's pre-frame, post-frame, item and frame-start events, field by field, through the timeline rollback settled on | `melee-oracle compare` |
| Full state | ssbm-rs playing the same replay | The whole state every tick, as the captured-state checks compare it, against ssbm-rs's memory | `melee-oracle diff`: runs from the match's start or a trace tick, stops at the first difference or unported function |
| Captured states | ssbm-rs's lockstep captures (memory at a real call) | A game function run from a real game state on both sides, then the whole state | `melee-capture`: imports a captured state into melee-sim (scheduler, joint trees and everything on them, fighters, the stage) and compares melee-sim's state with memory; round trips on real captures come back clean. leaf-check's `stage` tests run Final Destination's and Battlefield's setup and processes from captures, its `camera` tests every camera function, and its `effects` tests every effect function and spawn every effect id from real states |
| Leaf functions | ssbm-rs's ports | Math, collision geometry and other code whose inputs and outputs map directly | `leaf-check`: the RNG, math, the SDK's and HAL's vectors, matrices and quaternions, collision geometry, stage and environment collision, controllers and rumble, and HSD's scheduler, animation, joints, references, display lists and shapes |

**Replay events.** ssbm-rs plays the 40-replay smoke set to the same recordings as the original code, with documented entry-frame and off-screen-flag differences in 12. A melee-hd recording is compared with the original replay through ssbm-rs's own comparison (`ssbm_slippi::compare`). This covers VS matches only, and only what Slippi records.

**Full state.** Replays leave out most of the game: menus, single-player modes, stage objects, the camera and most fighter fields. ssbm-rs's runner, with `STATE_TRACE=FILE`, writes the game's raw state at the end of every engine tick: the RNG seed, the player blocks, the stage, the camera, and every fighter, item and fighter joint. `melee-oracle trace-check TRACE REPLAY.slp` checks a trace against the replay it ran: each frame's post-frame fighter positions and percents must equal the trace's, bit for bit, one tick per frame. Two full smoke replays (Dream Land, 13,779 frames; Pokémon Stadium, 13,671) pass with no difference; a full match's trace is about 14 MB. Slippi's pre-frame data doesn't line up as exactly, because it is sampled partway through a tick. Function-level lockstep doesn't carry over, because melee-hd's data no longer has the original's layout.

With `STATE_TRACE_MEMORY=FROM..TO` (ticks, or `1` for all; trace version 3), each tick also carries main memory: the 4 KiB pages that changed since the tick before, XORed with what they held, every nonzero page at the window's first tick. Version 4 adds the time base at each such tick's end, which the audio timeline starts from when the diff takes up a tick or seeds the boot state. The main thread's stack and the GX FIFO are left out, as neither is game state: since version 5 their bytes are held at zero and the rest of the pages they share is recorded (before, the whole pages were left out, the OS heap descriptors after the FIFO with them). A whole match with memory is about 250 MB in the silent DSP model and about twice that in the sample-accurate one. The oracle's traces are made with Show Player Names off (`SLIPPI_PLAYER_NAMES=0`, a setting Slippi Dolphin has too): that optional playback code draws the players' names over the match and makes HUD objects for them, which melee-hd leaves to the presentation. They're made with ssbm-rs's default, sample-accurate DSP model, which `Settings::from_replay` plays replays with, as Slippi Dolphin recorded them. That doubles their size, because the voices' state in audio memory then changes every tick: the Fox vs Sheik match's is about 525 MB, against 258 MB silent. The Fox vs Sheik Final Destination replay's is made so, from ssbm-rs's checkout:

```text
SLIPPI_PLAYER_NAMES=0 STATE_TRACE=local/traces/v5-mixed/Game_20260129T133652.trc STATE_TRACE_MEMORY=1 \
  target/release/ssbm-run "$SSBM_DISC" --replay Game_20260129T133652.slp --fields 100000 \
  --port all --known local/replays/known/Game_20260129T133652.txt
```

`melee-oracle diff TRACE REPLAY.slp` plays the replay in melee-hd and compares its whole state with the trace's memory after every engine tick, through `melee-capture`'s comparer: the scheduler and everything its GObjs hold (joint trees with their animations, references, display objects and shapes, the fighters, the stage objects), the stage, the camera, HSD's ID table, the audio driver's voices, the player blocks, the pad library, the button maps, the scene loop and its clocks, the VS match's controller, Slippi playback's state, the ruleset and UCF's pad buffer, the items' statics, and the display pass's statics (the current camera, the current and active lights with their slot masks, refraction's users, textures and projection, the background flash). Objects pair afresh each tick by where they are reached from. It reports the first tick (and its replay frame) that differs with the first 30 fields that do (`--all` for every one), or the first function no port covers (`code::unported`), named with its tick. The trace samples each tick before its frame's display pass, so the diff compares right after the tick and runs the display pass before the next one (`Match::step_replay_tick`, `Match::render`). The archives a started match loaded itself pair with where the original loads them by name (`Match::files`), a fighter's animations wherever its buffer holds them. `--fp hardware|slippi` picks the float mode (`gekko_fp`) the trace was made in: Slippi's for a replay as Slippi Dolphin plays it, the hardware's for a trace made with `--fp hardware`. To look past another part's seam, `--stand-in ADDR[=VALUE]` lets an unported function return (melee-sim's `stubs`), and `--ignore TEXT,...` drops the differences that contain one of the texts. Without options it starts the match from the replay's settings (`Settings::from_replay`), as Slippi's playback codes do, and runs from the trace tick that ran the match's first engine tick. With `--from TICK` it imports the trace's state at the end of that tick through `melee-capture`, compares the import back with the memory it came from, and plays on from there; `--against TICK` compares the import with a later tick's memory instead, which shows the comparison telling states apart. `trace-info`, `trace-dump` and `trace-world` inspect a trace with memory.

On the Fox vs Sheik Final Destination replay (v5-mixed), the match runs from its start in Slippi's float mode with no stand-in or ignore: it compares ticks 1 to 292 with no difference, the whole audio state and the sound handles the fighters and items keep included (Sheik's aerial needles among them), and stops in tick 293 (replay frame 169) at the fighters' hitboxes against her thrown needle (`it_802703E8`); taken up from tick 200 it reaches the same stop. The audio state compares from the first tick because the match's start runs, on the boot state's timeline, the boot's last scene's end (its last frame's render and copy, and the wait for the next retrace), the announcer's bank load, the scene's file loads where the original makes them (the fighters' `PlCo.dat` and their effect files among them) and the music's start. The pad library's queue follows the timeline: the polls the pad alarm queued while the scene set up (14 on this replay, beyond the one the boot state's queue held, which wrap the five-entry queue's `qwrite` from 2 to 1) are queued before the loop's flush, and the first round ticks on the one it leaves. In play the alarm (every 675,000 time base ticks) runs a little faster than video fields (675,675), so every thousand frames or so the scene loop finds a second poll queued by the time it counts them: that round ticks twice and renders once, and for the frames before it a poll waits in the queue. The diff queues each poll the timeline counts and runs the display pass only after a round's last tick. Taken up from any tick, the import compares back with no difference (ticks 120, 200, 400, 1000, 2500 and 5000 checked, the background flash's state and the magnifier's bubbles included), and play goes on until fighter and item code no port covers yet: from tick 120 to the fighters' hitboxes against her thrown needle (`it_802703E8`) in tick 293, from 400 to the same in 401, from 1000 to `ftCo_Cliff_Cam` in 1001, from 2500 to Sheik's KO past the bottom blast zone (`ftCo_800D3BC8`) in 2766, and from 5000 to the needle's hit check again in 5110, with no difference on the way. The four-player Final Destination replay with two Foxes (`Game_20260531T174953`, traced the same way) imports and compares back clean at ticks 200 and 6000 and stops at Jigglypuff's `ftPr_Init_UnkIntBoolFunc0` in the next tick. The Fox ditto benchmark (`local/bench/fox-fox-fd.slp`, two CPU Foxes on Final Destination) is traced in the hardware's float mode with ssbm-rs's trace-fifo build (`SLIPPI_PLAYER_NAMES=0 STATE_TRACE=local/traces/v5-mixed/fox-fox-fd.trc STATE_TRACE_MEMORY=1 ssbm-run "$SSBM_DISC" --replay local/bench/fox-fox-fd.slp --fields 100000 --port all --fp hardware`, whose replay check shows no divergence). With `--fp hardware` and no stand-in or ignore, it compares ticks 1 to 4695 with no difference (grabs, throws, the rapid jab, clanks, reflected blaster shots, powershields and Fox Illusion's afterimage among them) and stops in tick 4696 (replay frame 4572) at the first KO, past the top blast zone (`Player_GetMoreFlagsBit5`, in `ftCo_800D3158`). Taken up from tick 2000 it reaches the same stop; from tick 2300 it stops in tick 2356 on two unused hitboxes' `jobj` in a new item: words the item never writes and keeps from the freed item its block held before (`Pool::alloc_stale`), which the import doesn't carry over as the original's block holds them. Once a full tick runs, each frame's display pass follows; on these replays its first camera is the magnifier's (`ifMagnify_802FBBDC`), then the game camera's (`fn_800301D0`), both ported.

**Boot state.** A match that starts from the replay's settings can't hold what the boot and the menus left in the original's memory. Until they are ported, `diff` seeds it from the trace tick before the match's scene (the boot state; it needs a version 5 trace, for the time base and the audio heap), field by field from this list and never as a bulk copy (`tools/oracle/src/boot.rs`, `SEEDED`):

- the pad library: the queue's read and write positions, queued count and queued polls, the reset button, and the master, copy and game statuses (the seeding refuses a boot state where a rumble script the menus started still runs);
- the random seed (`*HSD_RandSeedPtr`) as the menus' draws leave it; Slippi's playback replaces it with the replay's when the match starts;
- the audio library: the AX library, the synth, the driver and the game's audio library as the boot initializes them and the menus leave them, with the sound bank they loaded and the audio timeline at the boot state's time base. Load timing isn't modeled: the bank is there from the start.

The fighters' addresses (`Settings::fighter_addresses`, which the address paragraph of [the engine notes](engine.md) explains) come from the trace's first tick, where the match has made its fighters. The seeding runs on the new state before anything of the match's scene (`Match::start_from`), and goes away once the boot and the menus are ported. It isn't platform state. `diff --boot-diff` prints what still differs between the seeded state and the boot state among the globals and statics the comparer covers: on the Fox vs Sheik replay only the button maps and the rumble data pointer (`lb_804D63C0`), which the scene's setup sets itself. HSD's ID table is empty at the boot tick, so there is nothing of it to seed, and which slots the GObj and heap pools reuse doesn't show, as objects pair by structure.

**Captured states.** Game code needs real states to run from: a fighter mid-action, with its joints, animations and stage. ssbm-rs's lockstep captures (`CAPTURE=DIR CAPTURE_FUNCS=NAME,...`) save main memory and registers at real calls. `melee-capture` finds which disc archives are loaded where (by header and contents; the game writes into some, such as fighters' action tables), then imports the state into a `Game`: the GObj scheduler with its processes, every joint tree with its animations, references, display lists and shapes, the fighters through their generated mirrors, and the stage (`stage_info`, the stage objects' user data with their variables typed for the stage, the stage parameters the game writes into, the collision geometry and islands, fog, lights, the game camera with its camera boxes, the player slots, game mode and controllers the camera reads, the random seed and HSD's ID table, and the effects and the particle system: every effect, efLib's globals and the fighters' deferred spawns, the effect banks, particles, generators, app-SRTs, point joints and the display's sorting state). Afterwards it compares a `Game` with memory, pairing objects by where they're reached from, so objects either side created since pair too. A port runs from the imported state while ssbm-rs runs the call from the same memory, and the two states are compared. Pointers the importer doesn't model yet (static data in the executable, item user data) are listed rather than guessed.

Besides single calls, a captured state can drive longer runs: leaf-check's `last_stage_ticks` runs Final Destination's stage processes alone for 6,400 ticks on both sides from one capture (phases 1 through 8 of its background cycle), `battle_stage_ticks` runs Battlefield's for 9,000, and the `on_state` tests call functions no capture reached on a real stage. The camera's tests also run perturbed copies of captured states (both sides start from the same changed memory) to reach values and branches the replays don't, and enter its special modes from VS states with random controllers. Where objects are freed and new ones made, both sides are paired afresh by where objects are reached from, since the heap reuses blocks by address and pools by last freed.

The audio driver is too (`leaf-check`'s `audio` tests): the importer brings in the driver's virtual voices and globals, the synth's nodes, loaded effects and globals, the AX library's voices, parameter blocks and stacks, and the sound bank (from its loaded copy), and the comparison checks them byte for byte. Their calls are saved with the runner's `CAPTURE_INTERACTED=1`, since every audio function masks interrupts. Their schedule has a check of its own: ssbm-rs's runner records every audio call game code makes, the audio frames and the audio state at every tick's end (`AUDIO_TIMELINE`), and the check replays the calls from a captured tick with melee-sim's timeline placing the frames, comparing tick start and end times and the whole audio state every tick over whole matches: a Final Destination singles and a four-player Battlefield teams replay (about 10,000 ticks each, clean), the singles again with ssbm-rs's sample-accurate DSP (`AX=1`, where the music refills read the disc), and a Pokémon Stadium match whose transformations load during play. The recorder also logs the game's own disc load requests, which the check replays with their waits. A fifth timeline starts at the boot's last tick (`AUDIO_START=0`) and replays the Final Destination match's scene entry: the library's bank choice and loads, the file loads and the music's start, with game code's own time between ticks taken from the log's time base and the entry's audio frames placed where the log has them. The sound bank functions also have saved calls of their own (`bank_calls`, `match_bank_choice`, `bank_group_remove`, `bank_deflag_moves`). The music stream's start and callbacks and the audio library's tick have saved calls of their own.

The VS match is checked the same way (`leaf-check`'s `vs` and `player` tests): the importer also brings in the player blocks, the pad library (queue, rumble and statuses), the button maps, the scene loop's state and frame clocks, the VS controller, the live standings, the pause screen and the player library's counters, and compares them back. Its captures come from the debug VS mode's random matches (`--mode e --matches`), whose code Slippi's playback codes don't patch (in replay runs they patch the VS scene's frame, setup and entry, and the pad library). Calls the runner never saves (those that load files or reach the audio driver) run from other functions' captured states; the player blocks' and the match's accessors run as random sequences from captured states, comparing every value read and the blocks after each step.

Fighter creation is checked from the states just before a VS match creates its fighters (`leaf-check`'s `fighter_create`): every slot's fighters are created on both sides and the whole state compared after each, the fighters' new joint trees, parts, attributes, DObj lists, dynamic bones, shadows and lights, the player blocks and the fighter globals with it. The debug VS mode reads fighters' files from the disc inside `Fighter_Create`, which the reference's side does from the disc while melee-sim's side is handed the same files.

The fighters' attack collision (`Fighter_procAttackColl`) is checked from its calls in running matches (`leaf-check`'s `fighter_procs`), each also run again with the other fighter's first hitbox switched on over the fighter and, by the call, the fighter's own box over it on the ground (clanks), its shield up, or both fighters' thrown boxes live: the hits, tips, clanks and shield hits, the damage logs, the knockback and damage result, the hit sounds and the statistics they reach, the effects they spawn compared with the rest, and the attack statistics stood in for on both sides. The same check runs the collision results (`Fighter_procCollResolve`), from real calls and again with one of the attack collision's results given (a tip, a shield hit, a clank, a dealt hit, a shield push, a held hitlag), the camera process and the fighters' light. The dynamic bones (`Fighter_procDynamics`) and the legs' reach (`Fighter_procIK`) are checked from their calls there and in a replay, again with wind sources given, a flat floor, other sizes, the air, a collider and Flat Zone, and with the legs' flags set and the model's root off the floor.

The fighter mirrors come from `tools/structgen`, which generates each game struct with an importer and a field-by-field comparer. `melee-oracle mirror-check TRACE` round-trips every fighter of a state trace through them.

**Replay playback and the Slippi ruleset.** A replay drives a melee-hd match through a port of Slippi's playback codes (`game::playback`): the replay's game start becomes the match's settings, its seed and each frame's recorded inputs and seed are inputs the frontend supplies (`Match::step_replay`, answering what Slippi's EXI device answers), the fighters get the recorded inputs in `Fighter_procInput`, the pad library renews from the newest poll each tick, team stock steals follow the replay, the match ends with the replay, and the playback and recording GObjs exist as in a replay run. The codes that don't change the simulation in a replay played forward are listed in `game::playback`'s documentation. The replay's code list makes the rules (`game::slippi`), and the codes the ported code reaches are ported natively.

Playback's own set also patches fighter code: in `ftCo_8009DD94` (`+0x2FC`, the bone dynamics' end) it sets up every dirty matrix of the fighter's model (each joint with `0x40` and not `0x800000` in its flags, children before siblings, instances included), which `Running::swing_chains` does in a replay, and in `ftCo_800DEBD0` it reads the debug level as 0, which a retail disc's is anyway. At the match's end the recording codes copy the results into the VS scene's exit data (`gmVsMelee_VsExitInfo`) and rank them with `gm_80166378`, which matters once the exit data is ported.

These ports are checked in leaf-check's `replay` tests against ssbm-rs's ports made with the codes (`ssbm_game::playback`), from captures of replay runs (their header shows how to make them): the recorded inputs with their raw sticks at UCF's thresholds, the first frame's settling, UCF's stick history and SDI, the off-screen limits, the frame reads, stock steals, the seed restored each frame, the general codes' costume rules and the settings themselves. leaf-check's reference runs the patched port of every function whose codes a capture's memory holds (`register_patched`), so the fighter and VS checks on replay captures check the patched behavior too; the VS checks' `place_players` covers neutral spawns, and `input`'s pad library sequences run with the playback patch on a quarter of the time. The replay's end (`replay_end`, ignored for now) agrees but for the audio driver: the quit plays the match's end sounds, which the VS code still hands the frontend as events where ssbm-rs's run drives the driver.

**Leaf functions.** `leaf-check` loads the disc's `main.dol` into ssbm-rs's runtime, registers every port, and calls them one at a time, so melee-sim's functions are compared with ssbm-rs's input by input, in both float modes. Inputs are special values, random bit patterns and values spread over each function's useful range. Changing one bit of a constant makes the checks fail.

## Rules

- Floats compare by bit pattern. One ULP is a divergence.
- External events (a disc read completing, a camera snapshot) are inputs, recorded and replayed like controllers, never compared as state.
- A known difference must be explained and listed per replay, as ssbm-rs's known-divergence files are; a blanket exception is never accepted.
